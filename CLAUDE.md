# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The Jekyll source for <https://justinhartman.co>. It is a content site built on a
**vendored copy** of the Minimal Mistakes theme — there is no application code beyond
Liquid templates, Sass, and a little jQuery (plus one stray Ruby script in `_playground/`).

## Commands

```bash
bundle exec jekyll build          # build to _site/
bundle exec jekyll serve          # local preview
./script/cibuild                  # build + html-proofer (see caveat below)
```

Ruby 3.1.7 (pinned by `.ruby-version`, matching the deploy workflow); every direct gem in
the `Gemfile` is pinned to the version in `Gemfile.lock`. Change one and change both — the
workflow's `bundler-cache: true` will fail on a Gemfile-only commit.

There is no test suite. `script/cibuild` builds, then runs:

```bash
bundle exec htmlproofer ./_site --disable-external --allow-hash-href \
  --ignore-files '/kitchen-sink\.html/'
```

**`cibuild` validates almost nothing — do not treat a green run as a check on your work.**
Two independent reasons: `--disable-external` skips external links by design, and every
internal link is emitted absolute against `site.url` by `absolute_url`, so nothing is left
to check. Worse, html-proofer 5.2.2 extracts *zero* links from these pages (Nokogiri finds
47 in the same file) — the failure is upstream of link extraction, so no flag tuning
(`--swap-urls`, `--root-dir`, `--checks`) changes it; a different html-proofer version is
the only lever. The real gate is `bundle exec jekyll build` succeeding.

`.travis.yml` still calls `cibuild`, but travis-ci.org is retired and the GitHub workflow
does not invoke it.

## Theme resolution — read this before editing templates

`_config.yml` sets `remote_theme: mmistakes/minimal-mistakes` and the `Gemfile` includes
`minimal-mistakes-jekyll`, but **neither is active**: `jekyll-remote-theme` is not in the
`plugins:` list, and there is no `theme:` key. The site renders entirely from the local
`_includes/`, `_layouts/`, and `_sass/` copies. Edit those files directly; do not expect
upstream theme changes to flow in, and do not "fix" a template by looking for it in a gem.

- Skin: `minimal_mistakes_skin: "justin"` → `_sass/minimal-mistakes/skins/_justin.scss`,
  interpolated by `assets/css/main.scss` (a custom skin derived from `contrast`).
- JS: `_includes/scripts.html` ships `assets/js/main.min.js`, a concatenation of
  `assets/js/_main.js` + `plugins/` + `vendor/`. No build task for this exists in the repo,
  so editing `_main.js` alone changes nothing — `main.min.js` must be regenerated by hand.

## Content model

Six output collections, each with its own permalink shape and its own `defaults:` scope in
`_config.yml`:

| Collection | Directory | Permalink |
|---|---|---|
| posts | `_posts/` | `/:categories/:title.html` (a top-level `permalink: /:title` is also set; the collection key governs) |
| pages | `_pages/` | `/:title.html` |
| projects | `_projects/` | `/:collection/:title.html` |
| linux | `_linux/` | `/:collection/:categories/:title.html` |
| technical | `_technical/` | `/:collection/:categories/:title.html` |
| playground | `_playground/` | no explicit `permalink` — Jekyll's collection default applies |

`_playground/` is `output: true` and is **not** in `exclude:`, so everything in it —
including `shopify_stats.rb` and `test.txt` — is published to the live site. Treat it as
public, not a scratch directory.

Behaviour like `toc`, `comments`, `author_profile`, `share`, and `sitemap` priority is set
per-collection in the `defaults:` blocks of `_config.yml`. To change how a whole collection
renders, edit the matching `defaults` scope — not the front matter of every file.

Conventions worth knowing:

- **All** collections use date-prefixed filenames, not just `_posts` (e.g. `_linux/2006-11-20-slug.md`).
- New content is scaffolded from `_templates/` (Octopress): `post_template: life`,
  `page_template: page`, `draft_template: draft` in `_config.yml` select which. Match an
  existing template's front matter when hand-writing a file.
- Images follow `/assets/images/<collection>/<slug>.jpg` for `header.overlay_image` and
  `/assets/images/<collection>/<slug>_580x300.jpg` for `header.teaser` and `image`. The 96
  WordPress-migrated posts instead point both keys at the same
  `/assets/images/uploads/<year>/<month>/` file (no `_580x300` variant exists for them).
- Adding `header.overlay_image` switches on the hero, which renders `page.excerpt` inside it.
  Posts whose body opens with raw markup (`<img>`, `<blockquote>`) would have Jekyll
  auto-excerpt that markup into the banner, so the 43 without an explicit `excerpt:` key set
  `header.show_overlay_excerpt: false`. Keep that pairing when adding a header image.
- Search is client-side lunr (`search_provider: lunr`, `search_full_content: true`);
  an algolia path exists in `_includes/search/` but is not selected.

## Licensing — affects where new files go

The README splits the repo three ways, and this is a real constraint:

- **CC BY-NC-SA 4.0** (content): `_data/ _drafts/ _linux/ _pages/ _posts/ _projects/ _technical/ _templates/ assets/`
- **AGPLv3** (software): `_playground/` — new original code belongs here
- **MIT** (theme): everything else

## Style

`.editorconfig` governs: UTF-8, 4-space indent and 80-column default; 2-space for
`.js .rb .json .yml .toml`, the `Gemfile`, and `.travis.yml`; markdown keeps trailing
whitespace. `_config.yml` uses column-aligned colons — match the surrounding alignment
when adding keys.

## Deployment

GitHub Pages via `.github/workflows/deploy-jekyll.yml` — every push to `main` builds and
deploys, so a commit there is a publish. Ruby 3.1.7, `bundler-cache: true`, then
`bundle exec jekyll build --baseurl <configure-pages base_path>` with `JEKYLL_ENV=production`,
uploaded as an artifact and deployed by `actions/deploy-pages`.

Because the workflow runs Jekyll itself rather than relying on Pages' built-in build, the
plugins outside the GitHub Pages allowlist (`jekyll-minifier`, `jekyll-algolia`, `octopress`,
`jekyll-last-modified-at`) work fine. Note `JEKYLL_ENV=production` means `jekyll-minifier`
only minifies in CI — local builds are unminified. There is no `CNAME`.
